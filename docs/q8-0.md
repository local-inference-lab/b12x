# Q8_0 packed A16 weights

Q8_0 stores one FP16 scale followed by 32 signed INT8 values. Each weight is
`FP32(scale) * INT8(value)`, rounded once to BF16 before computation. The
resident encoding is exactly 34 bytes per 32 weights, with no lookup table.

Dense GEMM and GEMV use `blockscaled.pack_weight(blocks, recipe="q8_0")`
with CUDA uint8 `[N,K/32,34]` blocks, K32 and N8 alignment. Preparation
retains tiled INT8 bytes and compact `[K/32,N,2]` scale bytes. Use the existing
`PreparationSession`, `BlockscaledQuery`, and `blockscaled.mm` lifecycle.

Fused MoE uses `PackedSource(format="q8_0")` and
`BlockQuantWeights(w13, w2, codec="q8_0")`. Raw expert tensors are
`[E,N,K/32,34]`; the shared tiled MoE engine currently requires H/I divisible
by 128. SiLU, ReLU², routing, and capacity contracts follow the IQ2 path.

The existing `b12x.sequence.embedding` API also accepts contiguous CUDA uint8
`[vocab,K/32,34]` Q8_0 blocks and writes BF16 to caller-owned output. It keeps
the raw row layout for direct lookup and widens row offsets to Int64 before
multiplication. Plan through `query_from_call` or `EmbeddingQuery` with
`weight_dtype="uint8"`, logical `width=K`, and byte `row_stride=K/32*34`.

Codec branches specialize at compilation. Dense/MoE staging accounts for the
larger INT8 payload and K32 scale cadence; table allocation and lookup are
absent. The IQ2 K256 contiguous-copy shortcut remains specific to IQ2 storage.
No activation quantization or full-matrix dequantization is performed.

Correctness tests cover every signed byte value, short K32 blocks, K tails,
finite FP16 scale extremes, exact BF16 lookup, mapped MoE routes, graph replay,
fixed callable reuse, and compact storage. Dense preparation races the existing
GEMV/GEMM tiles and split-K choices. MoE preparation races the route, tile and
pipeline choices described in [IQ2_XXS support](iq2-xxs.md).
